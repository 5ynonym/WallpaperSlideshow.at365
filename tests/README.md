# 回帰テスト

Windows と .NET 10 SDK がある環境で、リポジトリのルートから実行します。

```powershell
dotnet run --project tests/WallpaperSlideshow.RegressionTests.csproj -c Release
```

外部テストパッケージを使わないコンソール型のテストです。失敗時は非ゼロの終了コードを返します。
壁紙設定や同名プロセスの終了処理は実行しません。一時画像はテスト専用フォルダに作成し、終了時に削除します。

検証内容:

- 不正設定の拒否と、適用失敗時の正常設定保持
- 手動停止・画面ロック・RDPの停止理由の組み合わせ
- Fill / Center / Fit / Stretchの描画範囲とクリップの復元
- PNG / JPEG / BMPの読み込み後に元ファイルを削除しても利用できること
- サムネイルの寸法、破損画像・不存在画像の扱い
- 履歴メニューの子項目とホストしたコントロールの破棄
- 履歴メニューの開閉イベント30回で項目が解放されること
- 設定の置換保存・削除・再作成、不正JSONからの復旧、停止中の更新間隔変更
- 不存在フォルダの接続、監視エラーの模擬発生後とフォルダ再作成後の実ファイルイベント受信
- サブフォルダへのアクセス拒否を模擬しても、読める画像一覧が残ること
- ログの世代交代・同一エラーの抑制、終了処理の複数回呼び出し
- 遅い処理中にも要求側が待たないこと、処理の直列化、定期更新の重複防止
- 新しい要求への集約、停止・終了・UI通知失敗時の結果破棄とリソース解放
- 負の画面座標を含む複数画面の合成、一時BMPの削除、合成開始前のキャンセル
- 非表示フォームのメッセージ処理が遅いI/O中も動くこと、結果がUIスレッドで適用されること
- サムネイルの縮小と、キャッシュへの画像所有権の移動
- 子テストプロセスの終了時に、書き込み中の一時BMPが削除されること
- READMEの設定例が実際の設定パーサーで受理されること

実機での追加確認:

1. 手動停止後にロック・解除しても停止が維持される。
2. 停止中にモニターを接続・切断しても壁紙が再表示されない。
3. RDP接続・切断中は停止し、ローカルセッションに戻ると、手動停止やロックがなければ再開する。
4. 履歴メニューとサムネイルを繰り返し開閉して操作できる。
5. 大量画像・低速共有フォルダを指定し、走査中も停止・終了・トレイ操作が応答する。
6. 合成中に設定や画面配置を変更し、変更前の結果が後から反映されない。
7. 履歴サムネイルの読み込み中にメニューを閉じ、再度開いても正常に表示できる。

自動テストは実際の壁紙APIを呼ばず、遅いI/Oをゲートで模擬して競合を検証します。Windowsのロック・RDP・実機モニター接続、ネットワーク断によるOS側の待ち時間は上記の手動確認対象です。

設定の許容範囲:

| 設定 | 範囲 |
| --- | --- |
| IntervalSeconds | 1～2147483秒 |
| History.Limit | 0～1000件（0は履歴なし） |
| History.ThumbnailWidth / ThumbnailHeight | 1～2048px |
| History.MaxFileNameLength | 1～1024 |
| TileCount | 1～64枚 |
| TileMargin | 0～4096の有限値 |
| 各Padding | 0～65535px。接続中モニターには正の描画領域が残ること |

設定適用後の解像度変更で描画領域がなくなった場合、そのモニターの描画はスキップします。
